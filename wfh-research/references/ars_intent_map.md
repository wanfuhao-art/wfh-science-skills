# 研究意图与 ARS 能力

仅涉及研究生产时读取；本地进度、方案整理和研究设计不依赖 ARS。映射决定能力，不替作者决定研究结论。用户明确指定优先，缺常用输入由已选模式补料，不重新让用户选模式。

## 1. 选择与加载

用已加载 Skill 返回的基目录、宿主明确插件根或调用方明确提供的根定位 ARS。只读注册表、命令与选中技能的当前契约，不猜缓存版本、不读凭证。源码可读与工具可调用分开核对；当前 Skill 列表没有入口即未加载，不能用 Read 或自行写文本冒充 ARS 调用。

执行使用真实命名空间 `academic-research-skills:<skill>`；若当前宿主返回不同的真实注册名，以宿主及对应插件清单核对后为准，不用 wfh 插件名前缀调用外部技能。斜杠别名只从真实命令核对；默认内部用 Skill 调用，用户不需要抄模式名。

调用前读目标 SKILL 的模式分支及它要求的支持文件，来源预检和证据记录见 [交接协议](ars_handoff_protocol.md)。普通索引失效可读真实注册表定位；缺 Python 不阻断此项文本核对。用户反馈用 [研究者界面](user_output_protocol.md)，内部原始返回保留为证据，不原样贴出技术拒绝。

下表是内部映射；用户只见检索、综述、写作、审稿、改稿或格式整理。

## 3. 单节写作的范围验证

ARS 3.24.2 没有 `section`、`introduction-only` 等原生模式，full 指南排除“只要特定章节”，写作 agent 又支持按大纲逐节写和调整顺序。因此不能默认把单节请求伪装为已支持的 full 模式。

- 已有稿件、只改引言：用 revision 的明确范围，遵守作者逐条裁定、精确块和补丁链。不能因为只有一节就跳过这些条件。
- 从零新写一节：先读当前 `academic-paper/SKILL.md`、`references/mode_selection_guide.md` 和 `agents/draft_writer_agent.md` 对应输入、输出及范围要求；引言再读 `references/intro_title_rhetoric_guide.md`。用户授权的验证路径只允许在真实 Skill 内询问是否可按这些规则做受限写作，不新增虚假 mode，不单独派内部 agent 冒充核心技能。
- 给实际 Skill 的请求包含：仅目标章节、精确大纲项、字数、证据、产出路径、禁止扩写的其他章节；明确“先核对当前契约是否支持这个受限请求，不支持则停止并说明缺项或边界”。不以 `[direct-mode]` 逃避契约或作者确认，不谎称完整稿已完成。
- 若核心技能接受该范围，记录实际调用、接受边界、真实单节产出和未生成其他章节的检查；此为受限请求验证，不是正式新模式或普遍可用保证。
- 若无法支持，只解释当前不能从零单独写这一节，给“先整理本节提纲和证据”的一个动作，写作步骤保持未完成；不自动写全文或降级到另一个写作插件。

没有可调用的 Skill 时，最多验证范围约定和文本草稿，不标为“ARS 实际调用通过”。

## 4. 输入与结果解释

从真实已确认方案、步骤声明输入、术语和作者限制准备参数；只摘要当前动作需要的内容，附原文件路径，不让作者手填技术对象。真实内部产物原样带入，外部作者材料明示来源；未知来源先查明，不伪造身份和验证记录。不是每个模式都需要四个研究字段，按当前选中模式的输入要求。

改稿保留意见原文与作者逐条选择；严重程度、编辑语气或“继续”不等于作者接受所有意见。真实委员会分支只有作者明确指认机构时进入，不把普通审稿委员会当机构裁决。

结果回来先核对：实际调用、停止点、目标范围、产出、证据与未决。给研究者本次完成的研究动作、可读结果、尚缺信息及一个下一步；如仍在提问或配置确认，不记录正文生产完成。失败保留准确来源，由界面协议翻译两句话；必要确认仍向作者收集。审稿报告只读评估，格式转换只改排版，不暗改内容。

Word 实际交付需 Pandoc；PDF 需所选路径的排版编译器和字体；Markdown / LaTeX 文本不自动等于已生成对应文件。Python、库和完整仓库只在真实分支要求脚本时核对，不要求研究者预装所有开发依赖。
