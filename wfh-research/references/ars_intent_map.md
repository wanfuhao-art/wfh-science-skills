# 研究意图与 ARS 能力

> 仅涉及研究生产时读取；本地进度、方案整理和研究设计不依赖 ARS。
> 映射决定能力，不替作者决定研究结论；用户明确指定时以用户为准。
> 完整 35 个 mode 的清单在 [路由索引](skills_index.md)，只在核对时读。

---

## 1. 选择与加载

用已加载 Skill 返回的基目录、宿主明确插件根或调用方明确提供的根定位 ARS。只读注册表、命令与选中技能的当前契约；不猜缓存版本、不读凭证。源码可读与工具可调用分开核对；当前 Skill 列表没有入口即未加载，不能用 Read 或自行写文本冒充 ARS 调用。

执行使用真实命名空间 `academic-research-skills:<skill>`；若当前宿主返回不同的真实注册名，以宿主及对应插件清单核对后为准。斜杠别名只从真实命令核对；默认内部用 Skill 调用，用户不需要抄模式名。

调用前读目标 SKILL 的模式分支及它要求的支持文件；来源预检和证据记录见 [交接协议](ars_handoff_protocol.md)。用户反馈用 [研究者界面](user_output_protocol.md)，内部原始返回保留为证据。

## 2. 能力映射

| 能力 | 常见模式（示例，不是完整表） | 输出与停止点 |
|---|---|---|
| 检索与核实 | `deep-research`: quick / full / fact-check | 研究短报、报告或逐说法核查；不冒称系统综述 |
| 文献综述 | `deep-research`: lit-review / three-way-scan / systematic-review | 注释书目、对照短名单或 PRISMA 报告；系统综述先确认问题、范围与纳排 |
| 写作 | `academic-paper`: full / plan / outline-only / abstract-only / lit-review | 稿、提纲或摘要；缺文献先补所缺 |
| 审稿 | `academic-paper-reviewer`: full / quick / methodology-focus / guided / re-review | 评估报告；评估不是录用证明，不改稿 |
| 改稿 | `academic-paper`: revision / revision-coach / rebuttal-audit | 改稿、回应路线或覆盖性核对；不默默扩大范围 |
| 格式与投稿材料 | `academic-paper`: format-convert / citation-check / disclosure | 格式产物、引用报告或 AI 使用声明；格式通过不等于文献存在或支撑关系已验证 |
| 全流程 | `academic-pipeline`（仅用户明确要求时） | 全链；会改变逐步流程，使用前说明 |

规则：

- **默认由 wfh 选能力，具体 mode 交给 ARS 的路由或模式契约**；用户不需要说 mode。用户明确指定 mode 时优先。
- `sr-screener` 只在用户明确要求纳排筛选、试筛、裁决或筛选计数时进入；普通系统综述不自动进入。
- 作者已有文献库时，检索 / 综述优先让 ARS 走 corpus-first；wfh 只传 `passport.yaml` / `*_literature_corpus.yaml` 路径，不生成或改写 corpus。
- `academic-pipeline` 只在用户明确要一口气跑全链时选择；解释它将改变逐步流程。
- 跨阶段材料无明确研究目标时只问一个目标问题，不因材料像某阶段就派单。

## 3. 单节写作

- 已有稿件、只改一节：用 `revision` 的明确范围，遵守作者逐条裁定、精确块和补丁链。
- 从零新写一节：先整理本节提纲与证据，不把请求伪装成 `full`；当前 ARS 契约不支持时停下说明缺项或边界。
- 不新增虚假 mode，不用 `[direct-mode]` 逃避契约或作者确认。

---

## 4. 输入与结果解释

从真实已确认方案、步骤声明输入、术语和作者限制准备参数；只摘要当前动作需要的内容，附原文件路径，不让作者手填技术对象。真实内部产物原样带入，外部作者材料明示来源；未知来源先查明，不伪造身份和验证记录。不是每个模式都需要四个研究字段，按当前选中模式的输入要求。

改稿保留意见原文与作者逐条选择；严重程度、编辑语气或「继续」不等于作者接受所有意见。真实委员会分支只有作者明确指认机构时进入，不把普通审稿委员会当机构裁决。

结果回来先核对：实际调用、停止点、目标范围、产出、证据与未决。给研究者本次完成的研究动作、可读结果、尚缺信息及一个下一步；如仍在提问或配置确认，不记录正文生产完成。失败保留准确来源，由界面协议翻译两句话；必要确认仍向作者收集。审稿报告只读评估，格式转换只改排版，不暗改内容。

Word 实际交付需 Pandoc；PDF 需所选路径的排版编译器和字体；Markdown / LaTeX 文本不自动等于已生成对应文件。Python、库和完整仓库只在真实分支要求脚本时核对，不要求研究者预装所有开发依赖。
