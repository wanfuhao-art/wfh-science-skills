# 盘问自检与失败模式

> 只在每轮结束、会话收尾或出现异常时读取；规则见 [盘问协议](grilling_protocol.md)。

---

## 1. 每轮自检

- [ ] 本轮每题的前置都已定？
- [ ] 同轮没有相互依赖的题？
- [ ] 每题有且只有一种推荐策略（建议 / 无建议）？
- [ ] 实质性题零倾向词？
- [ ] 没有问可查事实？
- [ ] 依赖事实的题是否等到了结果？
- [ ] 术语 / MDR 是否即时落盘？
- [ ] 连续接受计数是否正确？
- [ ] 被推翻的决策是否重开并标注？

## 2. 结束自检

- [ ] 核心 8 题（或增删后）≤3 轮；加分支 ≤4 轮？
- [ ] 零个「本可查到」的事实问题？
- [ ] 实质性决策零推荐？
- [ ] TERMS / MDR / 台账齐全？
- [ ] FINER 已由用户评分，或标 `[UNRESOLVED]` 并记录接受？
- [ ] 停在确认门，没有提前动笔？

---

## 3. 常见失败模式

| 失败 | 表现 | 修正 |
|---|---|---|
| 事实题问成决策题 | 「你想投的期刊字数是多少？」 | 派 subagent 查，或标 `[待核验]` |
| 实质性题给建议 | 「我建议你主张关联」 | 改成 ⛔；只列选项与代价 |
| 一轮塞进依赖题 | Q8 与 Q4 同轮，Q4 一答 Q8 就作废 | 移到下一轮 |
| 术语批量补写 | 结束时一次性补 TERMS | 一确定就写 |
| MDR 泛滥 | 每个小决定都写 MDR | 三门槛全过才写 |
| 确认门变总结会 | 「我总结一下，然后开始写 Brief」 | 输出台账后停下，等明确确认 |
| 反谄媚失效 | 用户连说三次「是」，下一题仍给建议 | 计数器强制 ⛔ |
| 事实造假 | 查不到却写成「该刊要求 8000 词」 | `[待核验]` + 已查来源 |
| 提前收敛 | frontier 还有节点就说「差不多了」 | 列未问节点，继续 |
| FINER 漏问 | Brief 里 FINER 五项全空，靠 spec 门补录 | 确认门硬检查；用户必须明确接受 |
| 证伪条件未定就过门 | 台账里证伪条件是「未决」，仍然确认 | §8.1 硬检查；用户必须明确接受 |
| 分支套错 | 材料课题被问样本量与 EQUATOR | 按 [盘问树](grilling_tree.md) 选材料分支；不适用节点标「不适用」 |
| 轮次超预算 | 第 5 轮还在问 | 报告 scope 过大，先收窄；不硬塞 |
