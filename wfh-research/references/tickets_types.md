# 任务类型模板

> 只在写具体任务时读取当前类型；不需要一次读完五种。
> 规则、字段和最小层见 [任务规则](tickets_template.md)。

---

## 8.1 claim 任务（可裁剪骨架）

```markdown
# T01 — <任务标题>

- 类型：claim
- 状态：todo
- 对应主张：C1 — <主张原文，照录 BRIEF>
- 对应子问题：SQ1
- Blocked by：—
- 执行方式：direct
- 会话预算：M（≤90 分钟；输入 ≤6 文件；产出 1 份记录 + 1 图 + 1 表）
- 产出：`tasks/T01-<slug>.md`（本文件）；`tasks/assets/T01/F-C1-01-<slug>.png`；`tasks/assets/T01/TB-C1-01-<slug>.md`
- 独立验证：只读本文件 + `tasks/assets/T01/` + `BRIEF.md` 的 C1 行

## 输入

- `BRIEF.md`：C1 行、研究范围、适用的研究类型扩展
- `TERMS.md`：<相关术语>
- `decisions/<MDR>`：<相关方法决策>
- <数据文件路径>

## 1. 主张

<照录 C1，说明本条负责的验证或论证部分；理论 / 定性按已确认的证据与解释边界。>

## 2. 证据

| 证据 | 来源 | 状态 | 存放 |
|---|---|---|---|
| <数据集 / 谱图 / 文献> | <实验 / 仪器 / 文献> | 已有 / 待采集 / 待核验 / 待分析 | <路径> |

- `[待核验]`：<事实>；已查 <来源>；未确认原因 <...>。

## 3. 分析

- 方法：<统计 / 拟合 / 编码 / 对比>
- 判定规则：<什么结果算支持；什么算不支持；什么算证据不足>
- 不确定性：<N、重复数、误差线、检出限>
- 替代解释：<至少一个；能否排除>

## 4. 图 / 表

| ID | 类型 | 数据源 | 图注草稿 | 一句话结论 |
|---|---|---|---|---|
| F-C1-01 | 图 | <路径> | <展示什么；N；误差线> | <一句话> |
| TB-C1-01 | 表 | <路径> | <列与单位> | <一句话> |

## 5. 正文

- 目标章节：Results / Discussion / Methods
- 字数：<150–250>
- claim 强度：<关联 / 描述 / 有限机理归因>
- 边界句：<不能排除什么；不主张什么>

## 6. 引用

| 引用键 | 来源 | 核验状态 |
|---|---|---|
| [@key] | <DOI / URL / 书目> | 已核验 / [待核验] |

## 验收标准

- [ ] 产出存在，适用层齐全，省略层有不适用理由
- [ ] 证据可追溯（来源 / 状态 / 存放）
- [ ] 分析可复现（方法 / 判定规则 / 不确定性）
- [ ] 图 / 表有数据源与图注
- [ ] 正文与 C1 强度一致，无过度断言
- [ ] 引用可核验，无编造
- [ ] 结论为四选一 token
- [ ] 独立验证者只读本文件 + 产出 + BRIEF C1 行即可判断

## 结论

- 判定：待执行 / 站得住 / 部分站得住 / 站不住 / 证据不足
- 理由：<哪些证据支持；哪些不支持；哪些没排除>
- 下一步：<补证据 / 改主张 / 降级 / 停止>

## 风险与未决

- <具体失效模式>
- [UNRESOLVED] <...>；影响验收标准 <...>；解决者 <用户 / 实验 / 文献>

## 完成记录

| 日期 | 会话 | 变更 |
|---|---|---|
| — | — | 初始计划 |
```

## 8.2 其他类型的差异

按任务规则 §4 只保留当前类型和研究目标需要的层，将下表内容用于这些层；同时裁剪不适用的验收项并记录理由。claim 也可依研究类型省略无关图表、正文或引用；不要整份复制后留下空标题。

| 类型 | 改哪些层 | 额外验收 |
|---|---|---|
| `prep` | 1 改为支撑性主张（支撑哪些 C#）；3 改为「分析 / 人工动作 / ARS 调用」；4 改为 QC 图表；5 改为 Methods 数据段或检索策略段；6 改为数据 / 仪器溯源 | 返回物可追溯（样本 ID / 仪器 / 参数）；QC 通过（校准 / 空白 / 检出限 / 重复） |
| `ec` | 1 改为形式一致性主张；3 改为迁移规则（映射 / 批次 / 回滚点）；4 改为 before / after 对照；5 改为受影响段落清单；6 改为格式核验 | 映射表完整；试点通过；旧格式在其他章节未动；未改内容 |
| `revision` | 头部加「来源意见 / 意见簇原文 / 受影响 claim」；2 改为意见表（原文 / 类型 / 是否接受）；3 改为回应策略（改正文 / 补分析 / 解释不改 / 降级）；5 改为改动清单；6 改为 response 对应 | 意见簇逐条有回应；正文改动可指向；response 条目已写；未改 claim |
| `integrate` | 头部加「阶段 5 / 7」；2 改为 claim → 任务 → 产出位置 → 是否写入正文；3 改为合并规则（章节顺序 / 声音统一 / 冲突处理）；4 改为全局图表清单；5 改为整合结果；6 改为全局引用核验 | 每条 claim 有对应段落；术语一致；引用键齐全；未新增 claim / 未改强度；交付核对通过，适用原生检查记录齐全；阶段 7 每条意见有 response |

### 8.2.1 `prep` 的最小头部

```markdown
# T02 — <任务标题>

- 类型：prep
- 状态：todo
- 对应主张：—（支撑 C1、C2）
- 任务主张：<数据可用 / 测量可信 / 决策已定>
- 对应子问题：SQ1
- Blocked by：—
- 执行方式：human
- 会话预算：S（AI 会话 ≤30 分钟；人工机时另计）
- 产出：`tasks/T02-<slug>.md`；`tasks/assets/T02/raw/`；`tasks/assets/T02/logs/`
- 独立验证：只读本文件 + `tasks/assets/T02/` + `BRIEF.md` 的 C1 / C2 行
```

### 8.2.2 `ec` 的最小头部

```markdown
# T13 — 引用格式切换（expand）

- 类型：ec
- 阶段：expand / migrate / contract
- 状态：todo
- 对应主张：—（全局机械改动）
- 任务主张：新引用格式在试点章节可用，旧格式仍保留
- Blocked by：T12
- 执行方式：direct
- 会话预算：S
- 产出：`tasks/T13-ec-expand-citation-format.md`；`tasks/assets/T13/citation-format-map.md`；`tasks/assets/T13/pilot/`
```

### 8.2.3 `revision` 的最小头部

```markdown
# R01 — <意见簇标题>

- 类型：revision
- 状态：todo
- 来源意见：<审稿报告条目编号 / 原文首句>
- 意见簇原文：<逐条照录>
- 对应 claim：C<nn>
- Blocked by：—
- 执行方式：direct / ARS:academic-paper:revision / human
- 会话预算：S / M
- 产出：`tasks/R01-<slug>.md`；`artifacts/09-response.md` 的 R01 条目；正文补丁位置
```

### 8.2.4 `integrate` 的最小头部

```markdown
# T99 — 成稿整合（阶段 5）

- 类型：integrate
- 状态：todo
- 阶段：5 / 7
- 任务主张：全部 claim 在正文有对应段落，术语一致，引用键齐全，不新增主张
- Blocked by：T01, T02, ..., R01, ...
- 执行方式：ARS:academic-paper:full / direct
- 会话预算：L
- 产出：`artifacts/05-draft.md`；阶段 7 另加 `artifacts/09-response.md`
```
