# 决策三分法（Decision Classes）

> wfh-research 共享包 · 与 `grilling_protocol.md` 配套 · 2026-11-13
> 用途：每个 frontier 节点在**提问前**先分类。分类决定「能不能给建议」。

---

## 1. 三类定义

### 1.1 程序性（procedural）

**定义**：有外部规范、模板或工具可查；选择不改变科学主张，只改变呈现、格式或流程。

**判据**（全部满足）：

- 能在期刊指南、机构模板、软件文档、数据库说明里找到明确答案；
- 选错最多返工，不会让主张变强或变弱；
- 不涉及「研究贡献是什么」「证据够不够」。

**例子**：期刊格式、字数与图表上限、结构模板、引用风格、检索策略、数据存储库、统计软件与版本、投稿系统、排期。

**推荐策略**：✅ 默认建议 + 理由 + 可推翻。

**标注**：`类别：程序性`

---

### 1.2 学科惯例（conventional）

**定义**：学科共同体有默认做法；偏离需要理由，但做法本身不定义你的贡献。

**判据**（满足任一即可，且不落入实质性）：

- 同行默认这么做，审稿人会预期；
- 有指南或共识文件（报告规范、伦理流程、统计呈现）；
- 但「做到什么程度算够」仍取决于你的主张强度。

**例子**：样本量惯例与功效计算、报告规范（CONSORT / PRISMA / STROBE / ARRIVE / COREQ）、统计呈现格式、伦理审批流程、量表选择惯例、数据可用性声明格式。

**推荐策略**：✅「惯例 + 建议」，必须标注「这是惯例，不是事实，也不是唯一做法」；给出偏离的代价。

**标注**：`类别：学科惯例（惯例，不是事实）`

---

### 1.3 实质性（substantive）

**定义**：决定研究主张是什么、凭什么成立、如何解释、由谁署名、持什么伦理立场。

**判据**（任一命中即是）：

- 改变 RQ 或贡献声明；
- 改变证据与主张的对应关系（研究设计、证据来源、主张强度、分析策略、证伪条件）；
- 涉及机理归因、理论框架、结果解释；
- 涉及伦理立场、作者顺序、利益冲突披露的实质内容。

**例子**：RQ、贡献声明、研究设计、证据来源、主张强度、分析策略、机理归因、理论框架、结果解释、证伪条件、局限取舍、伦理立场、作者顺序。

**推荐策略**：❌ 不给建议。

**可以做**：

- 列出选项及其代价；
- 指出每个选项的逻辑后果（「主张因果需要能排除反向因果的设计」）；
- 用边界案例压力测试构念；
- 检验答案与已定决策是否自洽；
- 在用户给出答案后，指出它站不住的地方。

**不可以做**：

- 排序选项；
- 写「通常」「建议」「更好的做法」「主流是」；
- 给默认值、加粗推荐、说「如果是我」；
- 把建议藏在「供参考」里；
- 即使用户坚持，也不替用户选；只列选项与代价。

**标注**：`⛔ 这一题没有建议`

---

## 2. 分类流程（三问）

对每个待定节点依次问：

1. **这题有外部规范可查，且不改变主张？**
   → 是：**程序性**。
2. **学科有默认做法，偏离需要理由，但不定义贡献？**
   → 是：**学科惯例**。
3. **其余？**
   → **实质性**。

**安全默认：分类存疑 → 按实质性处理（不给建议），并在台账标「分类存疑」。**

宁可少给一条建议，也不要替用户做研究判断。

## 3. 边界案例

| 题 | 容易误判为 | 正确分类 | 理由 |
|---|---|---|---|
| 目标期刊 | 实质性 | 程序性（但可能反噬 Q1） | 期刊要求可查 → 程序性；若期刊层级改变贡献框架，触发重开，贡献声明仍无建议 |
| 样本量 | 实质性 | 学科惯例 + 实质性两层 | 功效计算是惯例；「多大证据强度可接受」是实质性，由用户定 |
| 统计方法 | 程序性 | 看情况 | 改变推断含义 → 实质性；只改呈现格式 → 学科惯例 |
| 报告规范 | 程序性 | 学科惯例 | 有 EQUATOR 等指南；适用性可查，但「是否充分报告」影响可复现性 |
| 伦理审批 | 实质性 | 学科惯例 | 流程有规范；伦理立场（能否接受某类设计）是实质性 |
| 表征手段（材料） | 程序性 | 实质性 | XPS / XAS / TEM 决定证据类型；仪器可及性是事实 |
| 仪器参数 | 实质性 | 不是决策（事实） | 分辨率、检出限可查；问用户前先查，查不到标 `[待核验]` |
| 引用风格 | 学科惯例 | 程序性 | 期刊或模板规定 |
| 作者顺序 | 程序性 | 实质性 | 署名是责任与贡献归属 |
| 数据共享 | 实质性 | 程序性 / 学科惯例 | 存储库与格式可查；「是否共享原始数据」若有争议 → 实质性 |
| 时间线 | 实质性 | 程序性 | 排期可建议；「能否按时完成」的事实由用户提供 |
| 研究设计 | 学科惯例 | 实质性 | 决定证据能否支持主张 |
| 理论框架 | 学科惯例 | 实质性 | 决定你如何解释结果 |
| 量表选择 | 实质性 | 学科惯例 + 实质性 | 量表心理测量学信息是事实；构念匹配是实质性 |
| 检索策略 | 实质性 | 程序性 | 数据库、检索式、时间窗可查；但「检索到什么程度算穷尽」影响主张边界，若用户在意则升为实质性 |

## 4. 复合题

一题内子项可分属不同类别：**分别标注、分别处理**。

示例（默认树的 Q13）：

```markdown
❓ **Q13 — 伦理、披露、署名与时间线**

13a 伦理审批流程：……
➡️ **惯例建议（学科惯例，不是事实）**：……

13b AI 使用披露：……
➡️ **惯例建议（学科惯例，不是事实）**：……

13c 作者顺序：……
⛔ **这一题没有建议**：……

13d 时间线：……
➡️ **默认建议**：……
```

禁止：因为整题「看起来是程序性的」，就给 13c 也附上建议。

## 5. 记录

台账每行必须有：

- `类别`：程序性 / 学科惯例 / 实质性 / 分类存疑；
- `接受推荐`：是 / 否 / —（实质性题填 —）。

分类存疑的行在备注里写「存疑原因」。确认门时，用户可以看到哪些决策拿过建议、哪些没有。
