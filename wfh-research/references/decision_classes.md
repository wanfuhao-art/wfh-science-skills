# 决策三分法（Decision Classes）

> 与 `grilling_protocol.md` 配套。分类决定建议的依据与确认责任；边界案例见 [边界案例](decision_boundary_cases.md)。

---

## 1. 三类定义

### 1.1 程序性（procedural）

**定义**：有外部规范、模板或工具可查；选择主要改变呈现、格式或流程，不改变科学主张。

**例子**：期刊格式、引用风格、软件版本、存储库格式、排期。

**推荐策略**：给默认建议、来源、理由与可替代方案；允许推翻。若选择影响主张，转按实质性处理。

### 1.2 学科惯例（conventional）

**定义**：共同体有默认做法，偏离需要理由；适用性仍取决于研究目标。

**例子**：报告规范、功效计算、伦理审批流程、统计呈现、量表使用惯例。

**推荐策略**：说明「这是惯例，不是唯一做法」，给来源、适用限制与偏离代价。惯例不能直接证明本研究设计充分。

### 1.3 实质性（substantive）

**定义**：决定研究问题、贡献、证据与主张的关系、设计、解释或责任归属。

**例子**：RQ、研究设计、分析策略、理论框架、机理归因、验证条件、伦理立场、作者顺序。

**推荐策略**：AI 可以提出有依据的候选与推荐，包括研究设计和解释；同时交代证据、假设、限制、备选与可能推翻推荐的条件，由研究者确认关键决定。证据不足时标为暂定建议，不冒充已验证结论。

伦理审批、签署、署名同意及利益冲突声明由相应责任人完成；AI 可解释规范和梳理贡献，不能代为签署或同意。

---

## 2. 分类流程（三问）

1. 是否改变研究问题、主张、证据关系、解释或责任？是 → 实质性。
2. 否则是否有明确外部流程规范？是 → 程序性。
3. 否则是否为学科默认做法？是 → 学科惯例；其余标「分类存疑」，注明待核实依据，按实质性确认责任处理。

分类在提问前完成。候选与建议遵守当前执行模式；ARS non-generation Socratic 的原生限制见 `grilling_protocol.md` §0.1。

## 5. 记录

台账保留 `类别`、`接受推荐`（是 / 否 / —，未给建议填 —）及来源。区分三个维度：`AI建议`、`作者已确认`、`证据已支持`；作者接受建议不等于证据成立。

编号 `Dxx` 只标识记录，语义由 `decision_key` 表达，如 `research_question`、`contribution`、`evidence_source`、`claim_strength`、`research_design`、`analysis_strategy`、`validation`、`ethics`、`publication_target`。引用写 key + 真实 ID；同 key 可有多条。旧台账无 key 时按标题和内容映射，歧义标待确认，不从编号猜含义，不批量迁移。

评分可附有来源的 AI 建议，单列依据和限制；不得冒充作者自评。FINER 原作者值、评分人、日期及来源原样保留，建议另列，不覆盖。
