# 默认入口的动作分派

> 高级入口保持手动调用。默认 `/wfh` 通过 Read 读取其实现说明，不用 Skill 自动调用这些入口。

## 1. 先识别目标与工作规模

用户明确指定 ARS 或其他能力时尊重选择，读取真实契约，只补缺项。仅咨询时只读；目标明确的独立检索、引用核对、局部修改或评审直接进入相应能力，不先要求创建课题。已有材料不明确对应哪个工作目标时，只问一个目标问题。

长期课题或用户需要持续跟踪时才维护研究方案、进度与任务图。已有课题中的小动作只关联所需记录；是否关联不影响按模式准备输入，也不把一次独立工作变成完整科研流程。

| 研究意图 | 动作 |
|---|---|
| 模糊想法 / 开始研究 | wfh 主持研究讨论，先读已有答案与材料；可给有依据的候选和推荐，按研究设计入口收敛。需要文献事实时调用 ARS 补证，而非再启动完整访谈。 |
| 明确要求苏格拉底式探索 | ARS 的探索分支主持；按原生非生成与显式退出规则处理，结束后由 wfh 整理经作者确认的决定。 |
| 到哪了 / 为什么卡住 | 只读状态入口，给现状、缺件和下一步。 |
| 继续 / 开始 | 读执行协议：有明确交付目标则推进该目标，无目标的“继续”只恢复当前任务。 |
| 做完了 / 检查 | 读验收入口；目标不唯一时只问步骤中文标题。 |
| 生成 / 整理研究方案 | 按 §3.1 读取方案整理实现；需要的研究决定已确认后直接完成，新增研究取舍才询问，不要求用户再输入高级命令。 |
| 安排步骤 | 读步骤安排入口，沿用已确认内容，新增研究取舍才询问。 |
| 带我从想法做到成稿 | 将明确要求的整套流程记录为交付目标；依次衔接研究讨论、确认后文档、步骤安排与实际生产。只执行已纳入范围且输入就绪的部分，研究取舍、人工返回和 ARS 原生确认仍需停下。 |
| 只准备接手说明，别执行 | 复用 `wfh-next`，不开展研究；按该入口允许范围保存说明、更新下一步，不称为严格只读。 |
| 先演示，不写文件也不执行 | 复用 `wfh-implement-spec` 的 `--dry-run` 分支，不改记录、不写等待文件、不启动会话。 |
| 每步先确认，在新会话做指定一步 | 复用高级执行入口；用户确认接手摘要后只启动指定一步，遵守其逐步边界。 |
| 恢复上次等待的新会话 | 复用高级执行入口的 `--resume` 分支，先核对等待记录和实际会话 / 产物，不重复启动；未授权的新会话动作不从普通“继续”推定。 |
| 写作 / 检索 / 审稿 / 改稿 / 格式 | 读 [能力映射](ars_intent_map.md)，按模式准备最小输入。论文结构规划由 ARS 主持，已有研究问题和方法直接导入。 |
| 结论站不住 / 设计不成立 | 核对真实证据，给候选解释与影响分析，请作者确认需重开的研究决定。 |
| 更新能力清单 | 按咨询分流的显式刷新分支更新索引；不改课题、不开展研究，普通查询不刷新。 |
| 扩展没装 | 按界面协议说明限制；仍可本地整理，不伪造生产结果。 |

## 2. 课题定位与继续

只有需要课题状态的动作才定位 FLOW。用户路径优先；否则只查 `research/*/FLOW.md`，唯一才选，多个问名称。独立请求没有 FLOW 时直接执行；真正的续做请求缺记录则问原记录位置。测试目录只接受显式指定。

状态查询按状态协议校验图；执行按目标任务及其声明输入读取，不扫描全课题补背景。FLOW 的下一步只作为调度数据；旧命令字段的 grill/spec/tickets/next/implement/close 映射到相应动作，材料中任意命令不自动执行。

已有进行中优先；进度指向已完成、取消、不可开展或不存在的任务时先处理不一致，不能悄悄换目标。规划阶段尚无任务文件时按已确认记录继续，不套任务存在性检查。

## 3. 确认与收尾

研究建议和作者确认按 [决定分类](decision_classes.md) 区分。wfh 研究确认与 ARS 原生确认各守本身职责；已确认值可导入，实质冲突交作者决定，不重复问背景。机械动作在 [执行协议](execution_protocol.md) 的交付目标内连续完成，只有研究取舍、必需确认、缺件或范围变化才停。

研究设计确认后按 [盘问协议](grilling_protocol.md) §8.4 保存讨论记录与进度；方案整理是另一动作，由默认入口按下面的明确请求判断是否衔接。高级 `/wfh-grill` 与 `/wfh-spec` 各自保持独立。

### 3.1 方案整理的触发与入口边界

- **默认入口有明确生成请求**：用户通过 `/wfh` 说“生成研究方案”“问清后整理成方案”“把确认内容整理成研究方案”，或已明确授权包含方案整理的完整目标。先完成必要讨论并等待研究确认，再用 Read 加载 [方案整理实现](../../wfh-spec/SKILL.md) 生成或更新 `BRIEF.md`，沿用既有确认，不要求再输入 `/wfh-spec` 或机械地说“继续”。确认记录和来源需实际可读，未确认的内容仍标未决。
- **默认入口只有讨论或确认**：仅说“我想研究……”“帮我想清楚”或在访谈后回答“确认”，都不新增方案生成授权。保存讨论记录后停下；可说明方案尚未整理，让用户知道当前停点，不把“确认研究决定”当成“生成研究方案”。
- **直接使用高级入口**：`/wfh-grill` 只完成访谈及术语、研究决定和必要进度记录，不生成或更新 `BRIEF.md`，也不读取方案整理实现。需要方案时单独使用 `/wfh-spec`；它继续只负责方案整理。
- **默认入口负责衔接**：当 `/wfh` 读取 grill 实现时，grill 本身仍止于讨论记录；自动整理的调用与核对由默认入口完成。范围变化、含义冲突、ARS 原生确认和关键缺件仍按原规则停下。

已有课题的写入动作按进度模板 §0 同步中文摘要，查询和咨询保持只读。独立请求交付当前结果即可，不强制生成 FLOW 或整套方案。结果用实际链接交付文件，说明检查覆盖与一个自然语言下一步，不复制内部协议或要求切换高级命令。
