# 3.2.2 发布说明与验证记录

## 发布内容

本版修正长期课题的上下文累积问题：已有任务图时，`/wfh` 的“继续”、已授权目标推进和 `/wfh-implement-spec` 默认把每个 AI 可执行步骤交给**新的执行子代理**完成，主会话只保留任务图、用户可见摘要和验收结论。插件与市场清单版本均为 `3.2.2`。

相对 3.2.1：

- 一个任务一个执行上下文；完成的子代理不复用于下一步，返工也新开一个。
- 交接只给指针：工作区、任务文件、逐项声明输入、必要协议路径、产出路径、验收要求和停点；不粘贴材料正文、上一任务对话或中间结果。
- 执行子代理只写声明产出与执行证据，不改任务状态、`FLOW.md` 或上游决定；主会话读取实际产物后验收并同步。
- 长稿、整稿或 `L` 预算任务可由只读验收子代理逐条核对，验收子代理与执行子代理不复用。
- 互不依赖、输入和产出不重叠的步骤可并行；共享产出或依赖前一任务证据时串行。
- 用户要求可观察的独立会话时才使用 `start_session`；`pending.json`、提示词路径和字段保持兼容。
- 宿主没有子代理能力时退化为独立会话或当前会话执行，并明确说明，不假称已隔离。
- 独立小请求没有任务图，仍在当前会话直接完成。

## 安装与兼容

安装方式不变，见 [README](../README.md)。已有课题无需迁移：`FLOW.md`、`BRIEF.md`、`TERMS.md`、`decisions/`、`tasks/` 的路径、状态 token 和「会话预算」字段含义保持不变；预算按单个子代理或独立会话计，不是主会话的累计上下文。回退本版技能改动即可恢复 3.2.1 的统一会话执行方式。其他行为变化见 [MIGRATION](../MIGRATION.md)。

## 本轮验证

验证日期：2026-11-15，对象为当前工作区的 3.2.2 候选版本。

| 检查 | 结果 | 范围 |
|---|---|---|
| 协议、入口与包内链接回归 | 14 项通过 | `python3 -I wfh-research/evals/check_contracts.py` |
| 评估工具回归 | 9 项通过 | `python3 -I wfh-research/evals/test_eval_tools.py` |
| 能力索引一致性 | `INDEX_CURRENT` | `refresh_index.py --check`，ARS 根显式传入本机 3.24.2 文档 |

新增契约检查覆盖：执行协议存在“一任务一上下文”“只传指针，不传正文”“执行子代理与验收子代理必须是不同上下文”；已移除“输入可容纳时在当前会话完成目标”的旧默认；任务模板声明每条任务一个全新执行上下文；五个入口的说明出现子代理。新增评估案例 `one-task-one-fresh-execution-context`，覆盖并行分派、验收后推进和子代理不复用。

这些检查只证明文档契约与离线工具通过，不代表模型在真实会话中已按此执行，也未实测宿主子代理的实际隔离效果、真实 ARS 调用、长时间课题的上下文占用或其他 CLI / Desktop 版本。发布前应在真实会话中演练一次“继续 → 子代理执行 → 验收 → 下一步新子代理”。
