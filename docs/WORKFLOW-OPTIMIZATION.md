# wfh-science-skills 工作流优化方案（v3.2）

> 日期：2026-11-13
> 状态：待确认
> 范围：只优化现有 9 个技能，不新增 matt 模块，不改 ARS，不改产物文件名。

---

## 0. 目标与非目标

### 目标

1. **更好用**：`/wfh` 一个入口、三个动作（开始 / 推进 / 验收），启动时不必先读两份长协议。
2. **更简洁**：协议按分支披露，去掉重复规则和无效否定；默认加载量减半。
3. **更贴科研**：盘问树按研究类型分支；六层证据链和验收深度按步骤类型 / 预算缩放。
4. **ARS 融合更稳**：wfh 只声明「作者确认了什么 + 这一步的边界」，不复制 ARS 的 Schema 与阈值。

### 非目标

- 不新增技能、不新增 matt 模块（证伪优先、诊断环、试点、项目地图都不加）。
- 不改 ARS 安装目录、不 fork、不往 ARS 写文件。
- 不改 `FLOW.md` / `BRIEF.md` / `TERMS.md` / `decisions/` / `tasks/` 的文件名和内部字段。
- 不重命名 9 个技能目录（兼容旧入口；只改 description 和正文）。
- 不改任务类型 token（`claim` / `prep` / `ec` / `integrate` / `revision`）。
- 不降低研究确认、证据和验收标准。

## 1. 现状诊断（可复核）

### 1.1 规模与加载

| 项 | 现状 | 问题 |
|---|---|---|
| 技能目录 | 9 个（1 默认 + 7 高级 + 1 共享包） | 数量本身合理，但默认入口承担了全部分流 |
| `SKILL.md` | 18–31 行，均 ≤60 | 体量达标，但压缩到接近电报体，可执行性靠读长协议补 |
| 共享协议 | 16 份，3339 行 | 其中 5 份超过 350 行 |
| 默认入口启动 | 先读 `user_output_protocol.md`（63 行）+ `dispatch_protocol.md`（34 行） | 简单查进度也要先读 97 行 |
| 失败翻译表 | 41 个内部标记挤在默认输出协议里 | 每次回复都要带着整张表 |
| `/wfh` description | 511 字符 | 其余 8 个约 106–148 字符，明显过重 |

### 1.2 重复与否定

| 规则 | 出现次数 | 影响 |
|---|---|---|
| 「每次只推进一步 / 不自动连跑」 | 4 | 多处维护，改一处容易漂移 |
| 「失败回复两句话」 | 4 | 同上 |
| 「六层证据链」 | 21 | 定义、引用、验收、模板混在一起 |
| 「确认门」 | 17 | 同上 |
| 「三门槛」 | 8 | 同上 |
| 否定式表达（不 / 禁止 / 不得） | 811 处 | 否定会放大被禁止的行为，且增加阅读负担 |

### 1.3 科研适配的粗糙处

1. **盘问树是固定的 14 题。** 默认包含样本量与功效、EQUATOR 报告规范等社会科学问题；材料/化学课题真正需要的是材料体系、对照、表征手段、工艺参数、机理主张。虽然 §3.1 有材料学覆盖表，但它不在默认树里，模型仍可能按 14 题走。
2. **六层证据链对所有任务一刀切。** `prep`（如仪器校准）不一定要图/表/正文/引用；`ec`（术语替换）不一定要分析层。协议说「按类型改写」，但没有给最小层清单，模型倾向于全填。
3. **验收深度不随步骤预算缩放。** `S` 预算的小步骤和 `L` 预算的整合步骤用同一套验收语言，小步骤显得过重。
4. **工程隐喻仍在任务类型里。** `ec`（expand–contract）、`integrate`、`revision` 是软件/出版混合词；内部 token 可以保留，但说明和应用场景应换成科研语言。

### 1.4 ARS 融合的脆弱处

| 位置 | 现状 | 风险 |
|---|---|---|
| `ars_handoff_protocol.md` | 93 行，复制 Schema 1 四字段、FINER 阈值、Passport/receipt 规则（Schema 27 次、Passport 17 次） | ARS 升级后双份真相漂移 |
| `ars_intent_map.md` | 65 行，20+ mode 静态表 | 与 ARS 35 个 mode 强耦合 |
| `ars_intent_map.md §3` | 约 20 行解释「ARS 没有单节模式」 | 对用户是噪音；一句话即可 |
| `skills_index.md` | 84 行，已生成 | 可保留为参考，不应成为默认阅读路径 |

### 1.5 一致性问题

1. `flow_template.md §2` 说 `Current task` 默认取 frontier 中的 tracer bullet；`state_protocol.md §3` 说优先保留合法 `doing`。两处应统一为「doing 优先，其次用户指定，其次 frontier 首个可启动」。
2. 用户可见文件仍有少量工程词：`ticket` 6 次、`Brief` 3 次、`MDR` 1 次（README / MIGRATION / SKILL 描述）。
3. `wfh/SKILL.md` 的 description 511 字符，触发词堆叠；可压到约 300 字符并保留全部触发场景。

## 2. 优化原则

1. **一个入口，三个动作。** 用户心智只有「开始 → 推进 → 验收」；高级入口只给明确只做单一动作的人。
2. **规则单一来源。** 每条规则只在一个文件定义，其他文件用指针；不再复制。
3. **按分支披露。** 核心规则常驻；类型模板、示例、边界案例按需读取。
4. **科研语言优先。** 用户可见文本不出现 frontier / claim / ticket / Brief / MDR / tracer bullet / Schema / Passport / 回执 / 错误码；内部 token 保留，但说明用研究语言。
5. **标准不降。** 作者确认、证据可追溯、结论四选一、失败两句话，全部保留。
6. **每批可回滚。** 三个提交分别对应入口、协议、ARS 融合，互不依赖。

## 3. 改动清单

### 提交 1：入口与界面（低风险）

**目标**：默认加载量减半，用户可见文本零工程词，修一处一致性。

| 文件 | 改动 |
|---|---|
| `wfh/SKILL.md` | 内联三行动作表（开始 / 推进 / 验收 / 查看 / 卡住），只在多阶段或意图不清时读 `dispatch_protocol.md`；description 压到约 300 字符 |
| `wfh-research/references/user_output_protocol.md` | 保留默认回复、两句话失败、文件中文用途；41 个失败标记移到新文件 `failure_translation.md`，只在失败时读 |
| `wfh-research/references/failure_translation.md`（新） | 原失败表原样迁移，加一句「只在失败时读」 |
| `wfh-research/references/flow_template.md` §2 | `Current task` 优先级改为「合法 doing → 用户指定 → frontier 首个可启动」，与 `state_protocol.md §3` 一致 |
| `README.md` / `MIGRATION.md` / 9 个 `SKILL.md` 描述 | 扫掉 ticket / Brief / MDR 等工程词；必须提文件名时附中文用途 |

**预期**：默认启动阅读 97 行 → 约 45 行；用户可见工程词 0；`/wfh` description 约 300 字符；`SKILL.md` 仍 ≤60 行。

### 提交 2：协议瘦身与科研适配（中风险）

**目标**：协议从 3339 行降到 ≤2500 行（约 -25%），盘问树和证据链更贴科研。

#### 2.1 按分支拆分大文件

| 原文件 | 拆成 | 读取时机 |
|---|---|---|
| `tickets_template.md`（812） | `tickets_core.md`（规则、字段、验收，约 300）+ `tickets_types.md`（§8 五种类型模板，约 350）+ `tickets_examples.md`（示例，约 150） | 建图读 core；写某类型读对应 types 段；需要样例才读 examples |
| `grilling_protocol.md`（471） | `grilling_core.md`（frontier / 轮次 / 格式 / 反谄媚 / 确认门，约 250）+ `grilling_tree.md`（默认树与轮次，约 120）+ `grilling_failures.md`（失败模式与自检，约 60） | 盘问读 core；排轮读 tree；收尾自检读 failures |
| `spec_template.md`（382） | `spec_core.md`（模板与写法规则，约 250）+ `spec_examples.md`（示例，约 130） | 合成读 core；需要样例才读 examples |
| `flow_template.md`（365） | `flow_core.md`（摘要 / 状态 / 任务图 / 台账，约 180）+ `flow_details.md`（阶段细节 / 未决 / 修订记录，约 180） | 更新进度读 core；查阶段细节读 details |
| `decision_classes.md`（171） | `decision_classes.md`（三类定义与判据，约 90）+ `decision_boundary_cases.md`（边界案例与材料学覆盖，约 80） | 分类读前者；拿不准才读后者 |

拆分只移动内容，不改规则；所有交叉引用同步更新，提交前跑链接检查。

#### 2.2 去重与正向改写

- 每条规则保留一个定义处，其他位置改成「见 X」。
- 把可正向表达的否定句改成目标行为。例：
  - 「不要问用户本可查到的事实」→「事实由系统查，决策由作者定」。
  - 「不要提前动笔」→「停在确认门，等作者确认后再写方案」。
- 目标：否定式表达减少 30%（811 → 约 570）；不为了减字删掉硬边界。

#### 2.3 盘问树按研究类型分支

保留三分法、frontier、确认门；把固定 14 题改为「8 题核心 + 按研究类型补充分支」：

| 分支 | 适用 | 补充问题 |
|---|---|---|
| 核心（所有课题） | 全部 | 贡献类型、证据来源、主张强度、研究设计、分析/解释策略、证伪条件、伦理与署名、目标期刊与格式 |
| 实证-定量 | 教育、心理、社科、临床 | 样本与功效、报告规范、图表计划 |
| 材料/化学 | 材料、电池、催化、表征 | 材料体系与对照、电压/温度/倍率等工艺窗口、表征手段与仪器可及性、机理主张、测试标准 |
| 定性/社科 | 访谈、案例、民族志 | 抽样策略、编码与可信度、立场与伦理 |
| 综述/元分析 | 系统综述、范围综述 | 检索策略、纳排标准、质量评估、综合方法 |
| 理论/方法 | 理论文章、方法论文 | 理论框架、论证结构、方法验证 |

- FINER 从「第 14 题」改为确认门的一次自评，不占提问轮次。
- 材料学覆盖表并入「材料/化学」分支，不再作为独立附录。
- 轮次预算从「14 题 ≤4 轮」改为「核心 8 题 ≤3 轮；分支按需追加，总轮次 ≤4」。

#### 2.4 六层证据链按任务类型取最小集

| 类型 | 必需层 | 可省层 |
|---|---|---|
| `claim` | 1 主张、2 证据、3 分析、4 图/表、5 正文、6 引用 | — |
| `prep` | 1 主张、2 证据、3 分析、6 来源 | 4 图/表、5 正文（除非产出就是方法段） |
| `ec` | 1 主张、3 迁移批次、4 before/after、5 受影响段落 | 2 证据（格式规则即可）、6 引用 |
| `integrate` | 1 主张、5 正文、6 引用 | 2–4（由上游任务提供） |
| `revision` | 1 主张、5 正文、6 引用/response | 2–4（由意见和原稿提供） |

#### 2.5 验收深度按预算缩放

| 预算 | 验收深度 |
|---|---|
| `S` | 产出存在、证据位置、结论四选一；不要求逐图逐引用复核 |
| `M` | S + 六层最小集齐全、分析可复现、图/表有数据源 |
| `L` | M + 独立验证者只读任务文件即可判断、跨任务一致性 |

**预期**：协议 ≤2500 行；盘问默认轮次减少；小步骤验收不再过重。

**验收**：原 SPEC 12 条行为仍成立（盘问 ≤4 轮、实质性决策无建议、claim 失败回环、任务图无环等）；10 条用户脚本通过；规则覆盖抽查（每条旧规则在新文件中仍可找到）。

### 提交 3：ARS 融合层（中风险）

**目标**：wfh 不再复制 ARS 的 Schema 和阈值；能力选择从「20+ mode 表」改为「7 个能力」。

#### 3.1 交接协议瘦身

| 原文件 | 改成 | 内容 |
|---|---|---|
| `ars_handoff_protocol.md`（93） | `ars_handoff.md`（约 40）+ `ars_internal_chain.md`（约 50） | 前者：来源判定、作者确认值检查、调用写法；后者：Passport / receipt / builder，只在 ars-internal 来源时读 |

保留的关键保护：

- **缺项即停**仍然由 wfh 预检承担（因为 ARS 普通 intake 实测不会拒绝缺 Scope）。
- wfh 只检查「四个必需值存在、非空、非 `[UNRESOLVED]`、来源是作者确认」；FINER 阈值和 Schema 语义引用 ARS 原文，不再复制。
- 内部链的 Passport / receipt 原样保留，只是移到附录。

#### 3.2 意图映射改为能力映射

| 能力 | 常见模式（示例，不是完整表） | 停止点 |
|---|---|---|
| 检索与核实 | `deep-research`: quick / full / fact-check | 报告与来源 |
| 文献综述 | `deep-research`: lit-review / three-way-scan / systematic-review | 书目与综合 |
| 写作 | `academic-paper`: full / plan / outline-only / abstract-only / lit-review | 稿或提纲 |
| 审稿 | `academic-paper-reviewer`: full / quick / methodology-focus / guided / re-review | 评估报告 |
| 改稿 | `academic-paper`: revision / revision-coach / rebuttal-audit | 改稿或回应 |
| 格式与投稿材料 | `academic-paper`: format-convert / citation-check / disclosure | 格式产物 |
| 全流程 | `academic-pipeline`（仅用户明确要求时） | 全链 |

- 默认由 wfh 选能力，具体 mode 交给 ARS 的路由或模式契约；用户不需要说 mode。
- 完整 35 mode 表保留在 `skills_index.md`（生成文件）里，只在需要核对时读。
- `ars_intent_map.md §3` 的单节写作说明压成三行：已有稿用 revision 限定范围；从零写先整理本节提纲和证据，不冒充 full；不支持就停下说明。

**预期**：交接协议默认阅读 93 → 约 40 行；意图映射 65 → 约 40 行；ARS 升级只需更新能力示例，不必改 Schema 文案。

## 4. 总验收标准（可观察）

1. **单入口**：10 条用户脚本都从 `/wfh` 或自然语言进入，不让用户选命令。
2. **零术语**：`check_outputs.py` 词汇检查 10/10；用户可见文件无 ticket / Brief / MDR / claim / frontier。
3. **一屏**：README 快速开始 ≤15 行；每个 `SKILL.md` ≤60 行；默认启动阅读 ≤50 行。
4. **科研适配**：材料/化学课题走材料分支，不被强制回答样本量与 EQUATOR；盘问总轮次 ≤4。
5. **证据不降级**：原 SPEC 12 条行为仍成立；close 仍要求逐条证据；缺证据不记 done。
6. **ARS 融合**：能力映射可读；交接默认 ≤40 行；ARS 升级只需改能力示例。
7. **索引一致**：`refresh_index.py --check` 通过；`verify_index.py` 10 项通过。
8. **可回滚**：3 个提交，每个可单独 `git revert`。

## 6. 需要你确认的取舍

1. **盘问树是否改为「8 题核心 + 按研究类型分支」？**
   - 建议改。理由：现在的 14 题对材料/化学课题有 3–4 题不适用，真正需要的材料体系、对照、表征手段又不在默认树里。
   - 不改的代价：盘问轮次偏多，用户要主动说「这题不适用」。

2. **`ec` / `integrate` / `revision` 要不要改成科研词？**
   - 现状：**没有改名，也不打算改名。** 这三个是任务文件里的内部 token，已有课题在用。
   - 建议：保留 token，只在用户可见的说明里翻译成「分批替换 / 成稿整合 / 改稿回应」。
   - 为什么列出来：`ec` 原意是软件里的 expand–contract；你提到自己做科研不是写代码，所以我确认了一下是否要换。换 token 会破坏已有任务文件和状态协议，代价大于收益，因此不做。

3. **ARS 预检是否保留「缺项即停」？**
   - 建议保留。理由：实测 ARS 普通 intake 不会拒绝缺 Scope；wfh 预检是真实保护。
   - 只删掉重复的 Schema 语义和 FINER 阈值文案，不删检查动作。

## 7. 不做什么

- 不新增 `wfh-debug` / `wfh-pilot` / `wfh-program` 等技能。
- 不引入 TDD、git worktree、issue tracker、PR 概念。
- 不把 ARS 的 35 个 mode 全部写进默认路径。
- 不为了减行删掉作者确认、证据追溯、失败两句话、结论四选一。
- 不在方案确认前改技能文件。
