# 九技能审查与修复记录

日期：2026-11-15。范围：默认入口、七个高级入口、内部共享包，以及 Python 索引与评估维护工具。本轮直接修复已确认的问题，不调整发布版本、不安装插件、不改 ARS 源码。

## 审查依据与结论

本项目以 Markdown 指令与共享协议定义行为，Python 仅承担离线维护。协议问题通过入口、共享规则、模板与示例的交叉核对确认；工具缺陷通过标准库回归测试复现。前者的“已修复”表示指令及引用已修改，不等于模型在真实宿主中的行为已经通过验收。

审查不绑定某个模型，也不要求迁移模型或 SDK。ARS 的源码兼容核对使用显式指定的 `academic-research-skills@3.24.2`，共五个技能、35 条模式 / 入口记录；源码可读不证明当前会话已加载或真正调用了这些入口。

**保留九个技能目录。** 默认入口负责自然语言分派，高级入口提供可独立使用的控制边界，共享包提供唯一协议来源。删除高级入口会失去只读、只准备、只验收和逐步确认的独立能力。可精简的重点是重复或过度强制的规则。

## 逐技能结论

| 技能 | 发现的问题与影响 | 本轮处理 | 保留 / 升级结论 |
|---|---|---|---|
| `wfh` | 没有课题的“只准备 / 先演示”会进入要求进度与步骤编号的分支 | 为独立请求增加准备与演示路径；根据目标和现有材料交付说明，不先建课题 | 保留默认入口，继续作为普通用户入口 |
| `wfh-ask` | 等待补件、等待裁决、范围内已完成可能被当作下一步漂移；真实启动后状态可能仍未开始 | 按执行 / 恢复、等待、完成说明分别检查；启动时由发起方同步进行中，查询仍只读 | 保留，查询与执行分离 |
| `wfh-grill` | 组合研究分支重复 Q 编号，按编号回答有歧义；重要决定口诀会绕过三门槛 | 组合前分配唯一编号并同步依赖和回答引用；重要决定仍逐项满足三门槛；跨会话回环读取持久未决记录 | 保留，单独调用仍止于讨论记录，不生成方案 |
| `wfh-spec` | 明确要求草稿仍先要求正式确认，无法进入草稿；示例将必需对照排除在范围外 | 显式草稿可使用有来源的未确认材料，保留待确认及冲突；不覆盖正式方案、不放行生产；修正碳酸酯基线范围；模板按需读取 | 保留，正式与草稿边界更明确 |
| `wfh-tickets` | 拓扑检查混用真实完成状态；漏声明前序证据；解释不改仍被要求正文补丁；术语表被无条件要求；草稿误用正式初始化 | 拓扑排序仅计算临时图入度；逐边声明前序文件与证明；按回应策略验收；术语 / 方法记录按需；草稿独立交付；取消依赖显式处置 | 保留；局部机械改动可用单个步骤，跨文件兼容迁移才用三阶段 |
| `wfh-next` | 阻塞步骤补齐材料后缺少恢复通道 | 原解除条件、依赖证明、输入与未决均满足时可准备恢复说明，准备本身保持原状态 | 保留，只准备、不执行 |
| `wfh-close` | 普通验收可能复活已取消步骤；科学否定被等同验收失败；后续步骤可能在解释失效后继续；取消历史永久卡住阶段完成 | 已取消且未重开时只读复核；分开判断交付与科学支持；持久记录受影响编号及解除条件；已确认取消且依赖已处置者可排除范围完成要求 | 保留，验收不补做生产、不替作者修改研究决定 |
| `wfh-implement-spec` | 单个等待记录可能被后一次启动覆盖；已启动与状态同步职责不清 | 一个未结束记录不得覆盖，结果不明先核对宿主；实际启动成功由发起方同步，状态部分写入失败停止调度 | 保留，每次指定一步、先确认再启动 |
| `wfh-research` | 多处状态与模板不一致；扩展位置未知被误说成未安装；独立调用技术日志混入用户交付；维护工具漏检与错误链接 | 同步共享规则、模板、失败翻译及索引；区分位置未知 / 未安装 / 未加载；内部证据与中文交付分开；修复工具并增加回归 | 保留内部包，不作为独立用户入口 |

以上流程缺陷的置信度为高：能从原规则组合得到具体冲突；修复后的真实模型行为仍需会话级验证。

## 主要修复位置与边界

### 状态、恢复与取消

- [状态协议](../wfh-research/references/state_protocol.md) §3–6：保留五种状态；恢复资格独立于依赖资格；等待或完成说明不再被一律判作漂移；已取消步骤不经普通验收复活。
- [执行协议](../wfh-research/references/execution_protocol.md) §3–4：执行方只写声明产物和执行证据，发起方在实际启动时同步进行中、验收后同步结果；提示词或失败的启动不构成已开展。
- [进度布局](../wfh-research/references/flow_template.md) 与 [初始化细节](../wfh-research/references/flow_details.md)：同步缓存更新职责、恢复候选、合法等待及草稿分支；不从模板倒推研究已确认。
- [回环模板](../wfh-research/references/reopen_template.md) 与 [盘问协议](../wfh-research/references/grilling_protocol.md)：即使正式回环包尚未确认，也在已有进度未决区保存受影响步骤、证据、解决者和解除条件；作者裁决及必要方案 / 步骤同步均有证据后才解除。

取消不等于完成。后续仍引用已取消步骤时，必须由规划显式调整依赖；验收不能自行删除依赖。科学检验得到否定结果时，按原交付标准判定是否完成，不为了回环虚构失败标准，也不让受影响后续自动执行。

### 研究设计、草稿与步骤安排

- [盘问树](../wfh-research/references/grilling_tree.md) §2：组合分支统一映射提问、依赖、轮次与回答，历史决定编号不重排。
- [方案入口](../wfh-spec/SKILL.md) 与 [方案规则](../wfh-research/references/spec_template.md)：先识别显式草稿请求；正式方案继续遵守确认依据，草稿逐项保留来源与待确认。
- [方案示例](../wfh-research/references/spec_examples.md)：将示例自身要求的碳酸酯基线对照纳入范围，只排除其余电解液；不为真实课题擅加对照。
- [步骤规范](../wfh-research/references/tickets_template.md) §5.6、§6.9–6.14 与 [类型骨架](../wfh-research/references/tickets_types.md)：入度拓扑排序不读取真实完成状态；每条依赖预先声明完成证明路径；改正文和解释不改分别验收；整合读取实际存在且相关的术语 / 方法记录。

草稿不覆盖正式方案或运行图，不将未确认阶段记为完成。未来证明可在规划时声明其精确路径，但声明不表示文件已经存在或前序已完成。

### 默认使用与失败说明

- [动作分派](../wfh-research/references/dispatch_protocol.md) §1.1：独立准备与演示不依赖课题定位、进度板或编号；只准备默认在回复中给说明，演示不写文件或执行。
- [研究者界面](../wfh-research/references/user_output_protocol.md) 与 [失败翻译](../wfh-research/references/failure_translation.md)：优先说明事实、缺口和当前动作；研究裁决所需理由不受固定两句话限制，未知失败模板只保留一个来源。
- [分流协议](../wfh-research/references/routing_protocol.md) 与 [ARS 交接](../wfh-research/references/ars_handoff_protocol.md)：定位失败不能断言未安装；源码可读、入口已加载、实际调用、交付完成分别记录；独立调用的原始参数和状态放内部证据，用户看到中文结果。

## 工具缺陷与复现覆盖

| 工具 | 原缺陷 | 修复及回归依据 |
|---|---|---|
| [回复检查器](../wfh-research/evals/check_outputs.py) | 固定只查 10 个案例，第 11 个及以后被漏掉；通过条件固定为 10；报告措辞可能暗示真实执行 | 根据案例清单与已保存目录合并检查，显式缺失回复仍计失败；按实际数量退出；结果仅声明词汇检查 |
| 同上 | 空集、重复编号及部分重跑的边界不充分 | 空集及非法编号报错，重复清单编号拒绝；重跑仅覆盖实际有回复的案例，其余保留原结果 |
| [索引生成器](../wfh-research/scripts/refresh_index.py) | 空 frontmatter 字段可能跨行吞下一字段；版本和入口角色约束缺失 | 空描述拒绝且支持 CRLF；插件与市场版本一致；高级入口保持用户可调用，共享包禁止自动及用户独立调用 |
| 同上 | 自定义输出目录时三条固定相对链接失效 | 所有包内导航相对实际输出位置生成；回归真实运行 CLI 保存到含空格的新目录，逐条检查链接并执行只读一致性检查 |

Python 工具缺陷已通过可执行回归验证。全部工具继续仅用标准库，不读取 settings、环境变量或凭据；ARS 文件只作数据读取，不执行其脚本。

## 精简与保留决定

已精简：局部机械改动的强制三阶段；不存在术语表时的硬性输入；解释不改的强制正文补丁；固定句数；重复的未知失败模板；方案合成时重复加载落盘骨架。

继续保留：七个高级入口、五种状态、原文件路径和旧编号；ARS 专业规则的唯一来源；只读与执行边界；作者确认与证据支持分开记录；已取消和已修订记录的历史。

本轮不删除历史设计文档、不合并独立入口、不修改发布版本。原有 `UX-REFACTOR-PROMPT.md`（历史重构提示词）保持未改动。

## 续轮：交接范围与验收收尾（2026-11-16）

本轮沿用 3.2.2 的单步骤隔离设计，修复两个协议缺口和一个工具误通过问题，不调整发布版本。

| 触发场景 | 改进与依据 |
|---|---|
| 独立会话已结束，直接调用验收，任务完成但等待记录仍未关闭，挡住下一步 | [状态协议](../wfh-research/references/state_protocol.md) §1、§6 统一负责等待记录收尾，[验收入口](../wfh-close/SKILL.md) 与 [执行协议](../wfh-research/references/execution_protocol.md) 引用同一规则。核对工作区和目标归属，确认执行停写；任务和进度同步成功后才关闭匹配记录。未完成、同步失败、执行仍在写入或结束未知时不关闭。写入前重读，收尾失败后的恢复不重跑已验收步骤。 |
| 原步骤分析 A、B，本轮只授权处理 A，但新子代理只收到旧目标 | 状态协议 §5 的交接必填本次授权、当前限制与来源；读取与执行取授权范围和原步骤范围的交集。排除输入不开放读取，子集完成不降低原标准或把整步标完成；无法独立执行时先回步骤规划。只准备说明明确标未授权执行。 |
| 空文件或纯空白回复被词汇检查判为通过 | [回复检查器](../wfh-research/evals/check_outputs.py) 增加 empty_reply 标记并判失败；重跑空回复不能回退使用原通过结果，CLI 返回失败。 |

原隔离场景第22例将“继续”误写为可推进三步，现改为明确授权三步交付的正例；新增第23–25例分别覆盖独立验收收尾、本轮范围传递、单说“继续”的单步边界。评估场景共25例，本轮仅更新定义，未运行模型行为评估。
