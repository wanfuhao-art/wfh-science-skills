# wfh 与 ARS 融合：职责、取舍与验证

日期：2026-11-14。当前版本：3.2.1。职责分工与下方四场景新旧对照记录于 3.2.0；3.2.1 的自然语言衔接与兼容检查另列末节。设计方向经研究者确认；Matt 是设计参考，主要融合对象为 ARS。

## 职责与唯一来源

| 内容 | wfh | ARS | 避免的重复 |
|---|---|---|---|
| 研究问题与设计 | 主持讨论、比较有依据的候选、记录作者决定 | 按需检索与分析；明确要求时主持 Socratic 探索 | 已有答案导入，只补缺项或冲突 |
| 研究方案与章节规划 | 研究问题、主张、证据、验证与未决 | 论文结构、章节提纲及任务内部专业规划 | BRIEF 不再兼任 Paper Blueprint |
| 输入 | 确定目标、范围、来源和适用材料 | 当前模式的输入契约、Schema 与阈值 | 不要求所有请求先填四字段或 FINER |
| 执行 | 在授权目标内调度、处理停点和记录进度 | 实际专业调用与原生必要确认 | 内部步骤不反复索取机械确认，不自动扩大到全流程 |
| 核验 | 核对交付、报告版本与研究一致性 | 引用、方法、实验来源与完整性等专业检查 | 取消第二套 M1–M7 强制门禁，不把未执行记通过 |
| 状态 | 发起方读取证据后统一验收和同步 | 返回真实产物、检查结果和停止点 | 执行方不抢写任务状态与 FLOW |

ARS 代码、安装目录和原生协议均未修改。运行时以实际加载的 ARS 版本为准，源码可读不等于宿主已注册入口。

## 与 Matt 的对应及保留差异

本地核对 Matt 1.3.1 的实际技能与发布清单。`grill-with-docs` 组合通用 grilling 与 domain-modeling；`research` 调查一手事实；`to-spec / to-tickets` 整理工程规格与步骤；实施层含 TDD、代码评审及提交行为。它们不能直接代替科研证据路线、人工实验和研究验收。

wfh 保留按依赖分轮、术语消歧、少量重要决定记录、可独立验收的工作单元和渐进加载；不引入 Matt 运行时依赖、不自动串联其手动入口、不将工程 TDD 或代码评审套作科研核验。

## 已确认的使用取舍

- AI 可提出候选及推荐，但必须解释依据、限制和备选；AI 建议、作者确认、证据支持分别记录。
- 跨学科使用问题、主张、证据和验证为骨架。实验、计算、定性、综述和理论只采用适用要求；省略项需给理由，既有任务标准不能静默降低。
- 独立请求直接交付，长期课题才持久维护全套记录；明确目标内连续执行，关键研究决定、原生确认、人工返回、关键缺件或范围变化时停。
- 原始作者评分和来源保留，AI 评分建议单列。FINER 只在任务契约需要时收集，尺度和阈值读取 ARS 原文。
- Dxx / Txx 是身份，不编码固定含义。新决定可加 decision_key，旧决定按实际标题与内容读取；样板任务按真实 ID 记录。
- 交付完成与科学支持程度分开，检验得到否定结果也可满足原交付标准；改变解释和后续方案由作者确认。

## 检查范围与复现

静态检查入口为 [check_contracts.py](../wfh-research/evals/check_contracts.py)，覆盖发布清单、实际技能入口、可用相对链接、现行协议矛盾与关键来源边界。它检查文档约束，不证明模型一定遵守。

索引验证使用 [verify_index.py](../wfh-research/scripts/verify_index.py)；维护时通过 `--ars-root` 显式提供 ARS 文档根。索引只保存稳定身份和内容指纹，不记录本机安装路径。

提示词演练场景保存在 [evals.json](../wfh-research/evals/evals.json)。对照使用修改前快照和本版协议，隔离运行同一组场景，输出调用计划与停点；ARS 调用为模拟，不生成真实科学结果。原始运行曾放本地 `.scratch/ars-fusion-evals/`，不作为独立克隆后的既有证据。本地 `.scratch/` 运行材料已在项目清理时移至废纸篓，可恢复；本文中的这些路径是历史记录。

## 3.2.1：自然语言衔接与文档交付

默认入口补齐查询、接手准备、只演示、恢复等待工作、指定新会话逐步执行与只验收的自然语言表达，复用高级入口实现和原有权限范围。明确的多阶段交付目标按范围接续；普通“继续”只恢复当前工作，规划阶段没有任务图时也能恢复文档整理或步骤安排。

高级步骤保持独立：单独 `/wfh-grill` 按 [盘问协议](../wfh-research/references/grilling_protocol.md) §8.4 保存术语、研究决定和必要进度，不生成或更新研究方案；`/wfh-spec` 单独负责整理或更新方案。普通用户通过 `/wfh` 明确要求生成 / 整理方案时，才由默认入口按 [动作分派](../wfh-research/references/dispatch_protocol.md) §3.1 在研究确认后衔接，无需另输高级命令。仅讨论或确认研究决定不构成方案生成请求。已授权的整理保存失败不记完成，恢复只补缺项。

用户考虑 ARS 衔接成本后，本版保留原文件名、路径、兼容字段和状态值，没有引入中文新布局。研究方案与决定记录增加中文阅读摘要，进度沿用既有中文摘要；用中文用途链接实际文件。没有适用术语或重要决定时不创建空文件，原有方法决定的三门槛保持不变。

验证分开记录：

- 13 项协议静态检查（含高级 grill 不加载 spec、默认入口仅在明确生成请求下衔接的回归约束）、10 项索引回归通过，来源索引刷新并检查为 `INDEX_CURRENT`。这些是文档与索引检查，不是技能真实运行证据。
- 对照本轮修改前的 Git 版本，ARS 交接协议与内部链原文未变，九个入口的身份及调用限制未变；`RQ Brief`、研究问题 / 子问题 / 评分 / 范围标记及 FLOW 状态字段格式保留。此检查只说明这些兼容面没有改变，不证明真实接收。
- [演练定义](../wfh-research/evals/evals.json) 的 id 5 已调整为“默认入口明确生成请求”与“高级 grill 仅确认决定”的对照；id 10 覆盖默认入口只讨论、未要求生成，id 11 覆盖高级 grill 保留旧方案。id 9 的恢复场景明确限定为此前已获方案生成授权。这些修订场景尚未重新运行模型演练。
