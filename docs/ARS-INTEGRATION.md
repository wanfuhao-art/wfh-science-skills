# wfh 与 ARS 融合：职责、取舍与验证

日期：2026-11-14。实现版本：3.2.0。设计方向经研究者在本次访谈确认；Matt 是设计参考，主要融合对象为 ARS。

## 职责与唯一来源

| 内容 | wfh | ARS | 避免的重复 |
|---|---|---|---|
| 研究问题与设计 | 主持讨论、比较有依据的候选、记录作者决定 | 按需检索与分析；明确要求时主持 Socratic 探索 | 已有答案导入，只补缺项或冲突 |
| 研究方案与章节规划 | 研究问题、主张、证据、验证与未决 | 论文结构、章节提纲及任务内部专业规划 | BRIEF 不再兼任 Paper Blueprint |
| 输入 | 确定目标、范围、来源和适用材料 | 当前模式的输入契约、Schema 与阈值 | 不要求所有请求先填四字段或 FINER |
| 执行 | 在授权目标内调度、处理停点和记录进度 | 实际专业调用与原生必要确认 | 内部步骤不反复索取机械确认，不自动扩大到全流程 |
| 核验 | 核对交付、报告版本与研究一致性 | 引用、方法、实验来源与完整性等专业检查 | 取消第二套 M1–M7 强制门禁，不把未执行记通过 |
| 状态 | 发起方读取证据后统一验收和同步 | 返回真实产物、检查结果和停止点 | 执行方不抢写任务状态与 FLOW |

ARS 代码、安装目录和原生协议均未修改。运行时以实际加载的 ARS 版本为准，源码可读不等于宿主已注册入口。

## 与 Matt 的对应及保留差异

本地核对 Matt 1.3.1 的实际技能与发布清单。`grill-with-docs` 组合通用 grilling 与 domain-modeling；`research` 调查一手事实；`to-spec / to-tickets` 整理工程规格与步骤；实施层含 TDD、代码评审及提交行为。它们不能直接代替科研证据路线、人工实验和研究验收。

wfh 保留按依赖分轮、术语消歧、少量重要决定记录、可独立验收的工作单元和渐进加载；不引入 Matt 运行时依赖、不自动串联其手动入口、不将工程 TDD 或代码评审套作科研核验。

## 已确认的使用取舍

- AI 可提出候选及推荐，但必须解释依据、限制和备选；AI 建议、作者确认、证据支持分别记录。
- 跨学科使用问题、主张、证据和验证为骨架。实验、计算、定性、综述和理论只采用适用要求；省略项需给理由，既有任务标准不能静默降低。
- 独立请求直接交付，长期课题才持久维护全套记录；明确目标内连续执行，关键研究决定、原生确认、人工返回、关键缺件或范围变化时停。
- 原始作者评分和来源保留，AI 评分建议单列。FINER 只在任务契约需要时收集，尺度和阈值读取 ARS 原文。
- Dxx / Txx 是身份，不编码固定含义。新决定可加 decision_key，旧决定按实际标题与内容读取；样板任务按真实 ID 记录。
- 交付完成与科学支持程度分开，检验得到否定结果也可满足原交付标准；改变解释和后续方案由作者确认。

## 检查范围与复现

静态检查入口为 [check_contracts.py](../wfh-research/evals/check_contracts.py)，覆盖发布清单、实际技能入口、可用相对链接、现行协议矛盾与关键来源边界。它检查文档约束，不证明模型一定遵守。

索引验证使用 [verify_index.py](../wfh-research/scripts/verify_index.py)；维护时通过 `--ars-root` 显式提供 ARS 文档根。索引只保存稳定身份和内容指纹，不记录本机安装路径。

提示词演练场景保存在 [evals.json](../wfh-research/evals/evals.json)。对照使用修改前快照和本版协议，隔离运行同一组场景，输出调用计划与停点；ARS 调用为模拟，不生成真实科学结果。原始运行放本地 `.scratch/ars-fusion-evals/`，不作为独立克隆后的既有证据。

本次结果：11 项融合静态检查、10 项既有索引回归通过；来源索引刷新后检查为 INDEX_CURRENT，git diff --check 通过。首次静态检查有一项将英文 non-generation 误判为缺失中文“非生成”，修正检查器后通过，没有更改原生边界。

| 模拟场景 | 修改前 | 本版 | 观察 |
|---|---|---|---|
| 独立引用核对 | 3/3 | 3/3 | 原有模式特例也能直接处理；本版统一接口以消除其他分支的全量预检冲突 |
| 理论研究与建议 | 2/3 | 3/3 | 本版能给有条件的推荐，保留证据缺口与作者决定 |
| 目标内推进 / 范围变化停点 | 2/3 | 3/3 | 本版在授权目标内接续，并保留原生确认停点 |
| 专业检查覆盖与版本 | 2/3 | 3/3 | 本版不套实验型七项门禁；两版都拒绝用旧报告覆盖已改变的新稿 |

演练页面见 [新旧输出与断言](ARS-FUSION-EVAL.html)，页面内 With Skill 为本版，Without Skill 为旧版。共四场景、每版每场景一份样本，由每版一个代理顺序处理，未盲评；期望和断言已随题目提供，分数只反映这些模拟路由方案。未测单场景成本、速度或统计稳定性，页面中成本字段的 0 是汇总器缺省值。

源码基线为 ARS 3.24.2：没有宿主真实 ARS 调用的接收、引用核验、输出生成或长期稳定性证据，不能据此宣称生产通过。本次没有把未通过的真实集成项目改写成已通过。
