# 开始、推进、验收

先读 [研究者界面](../wfh-research/references/user_output_protocol.md) 和 [动作分派](../wfh-research/references/dispatch_protocol.md)。用户说研究意图即可，不要求选择命令或模式。

1. 明确指定其他能力时尊重用户；只问进度就只读；说继续就开展已授权当前一步；说做完了就验收。
2. 已有课题先定位指定或唯一进度文件；多个只问课题名称。先读取已有答案和当前步骤，不重问背景。
3. 开始时问清问题、确认研究决定、整理方案与步骤；每个必要研究确认保留。
4. 推进时按已验证依赖和输入执行当前一步；人工实验只给动作与返回物，不假装完成。
5. 验收时读真实证据，更新进度；结论或设计站不住先请作者确认重新讨论哪个决定。
6. 仅实际需要生产时读 [ARS 能力选择](../wfh-research/references/ars_intent_map.md)；按用户研究意图选能力、准备输入和解释结果。
7. 各动作读取下表所指实现后在本入口继续，不让用户再换命令；高级入口只通过 Read 读取，不调用被设为手动的技能。

| 当前动作 | 按需读取实现 |
|---|---|
| 问清设计 | [研究设计](../wfh-grill/SKILL.md) |
| 整理已确认内容 | [研究方案](../wfh-spec/SKILL.md) |
| 安排初版或改稿步骤 | [步骤安排](../wfh-tickets/SKILL.md) |
| 只查看进度 | [只读查询](../wfh-ask/SKILL.md) |
| 准备接手说明 | [接手准备](../wfh-next/SKILL.md) |
| 开展当前一步 | [执行规则](../wfh-research/references/execution_protocol.md) 默认入口分支 |
| 证据验收 | [验收](../wfh-close/SKILL.md) |

收尾只说现在做到哪、做了什么和一项下一步。只生成说明不算执行；读源码不算生产调用；记录与证据不一致先停下核对。文件路径保留，回复附中文用途。每次只推进一步，不自动连跑。
