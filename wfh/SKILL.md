# 研究设计、推进与交付

先读 [研究者界面](../wfh-research/references/user_output_protocol.md)。用户只需描述研究意图，系统选择实现并衔接后续动作；高级入口保留给需要单独控制某一步的用户。

## 判断当前动作

| 用户目标或说法 | 动作与按需读取 |
|---|---|
| 想研究某个问题 / 比较设计 | wfh 主持讨论，读 [研究设计](../wfh-grill/SKILL.md)，复用已有答案，可给有依据的候选与推荐；确认后保存讨论记录，是否整理研究方案按动作分派 §3.1 判断 |
| 生成研究方案 / 问清后帮我整理方案 / 更新已有方案 | 读 [研究方案](../wfh-spec/SKILL.md)，所需研究决定已确认后直接整理，保留来源、主张边界和未决；不要求用户另输高级命令 |
| 安排长期课题步骤 | 读 [步骤安排](../wfh-tickets/SKILL.md)，按证据和依赖组织 |
| 看看进度 / 为什么卡住 / 怎么做 | 读 [只读查询](../wfh-ask/SKILL.md)，只查看或解释，不改记录、不开始研究 |
| 更新能力清单 | 读查询入口的显式 `refresh` 分支，只按 [咨询分流](../wfh-research/references/routing_protocol.md) 刷新能力索引，不开展研究；普通查询不刷新 |
| 继续 / 完成当前目标 | 读 [执行协议](../wfh-research/references/execution_protocol.md) 默认分支，在已授权目标内执行、核对和同步 |
| 带我从想法做到成稿 | 读 [动作分派](../wfh-research/references/dispatch_protocol.md)，先明确交付范围，衔接讨论、文档、步骤安排和实际研究；遇到必需决定或缺件时停下 |
| 先准备交给下一次会话的说明，别执行 | 独立请求按 [动作分派](../wfh-research/references/dispatch_protocol.md) §1.1 整理说明；已有课题读 [接手准备](../wfh-next/SKILL.md)，仅准备，不开展研究 |
| 先演示怎么做，别写文件也别执行 | 独立请求按动作分派 §1.1 只展示；已有课题读 [高级执行](../wfh-implement-spec/SKILL.md) 的 `--dry-run` 分支；均不写文件、不启动会话 |
| 在新会话做这一步，每步先让我确认 | 读高级执行入口，确认接手摘要后只执行指定一步；不把普通“继续”理解为开新会话 |
| 恢复上次等待的新会话工作 | 读高级执行入口的 `--resume` 分支，核对既有等待记录与实际产物，不重复启动 |
| 检索 / 引用核对 / 写作 / 审稿 / 改稿 / 格式 | 读 [ARS 能力选择](../wfh-research/references/ars_intent_map.md)，按模式准备所需输入；论文结构规划交 ARS 主持 |
| 做完了 / 只检查这一步，别补做 | 读 [验收](../wfh-close/SKILL.md)，区分交付完成与科学支持程度；只验收时不生产缺失结果 |
| 原解释或设计被否定 | 读 [回环](../wfh-research/references/reopen_template.md)，展示证据及候选路径，请作者确认改变哪些决定 |

独立小请求直接处理，不先建立课题、补完整方案或评分。需要持续跟踪或交付完整设计文档时才维护 FLOW；多阶段材料、意图不清或目标包含多个步骤时读动作分派。实现通过 Read 加载，不自动调用手动高级技能，也不让用户选择内部模式或参数。

## 完成边界

同一授权目标内连续完成准备、实际调用、结果检查和记录同步。方案整理的触发按 [动作分派](../wfh-research/references/dispatch_protocol.md) §3.1：明确请求生成方案时，研究确认后直接衔接；仅讨论或仅确认研究决定时，保存讨论记录后结束。遇新研究决定、ARS 原生必需确认、人工返回物、关键缺件或范围变化时停下。单说“继续”只恢复当前步骤，不授权整课题连跑。

AI 建议、作者已确认和证据已支持分别记录。只生成说明或读取源码不算 ARS 调用，文件存在不等于结论成立。已有课题记录与证据不一致时先核对；独立请求不强制创建进度文件。收尾说明实际产物、检查范围、遗留和一个自然语言下一步。
