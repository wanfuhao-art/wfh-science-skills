# 研究设计、推进与交付

先读 [研究者界面](../wfh-research/references/user_output_protocol.md)。先识别目标与工作规模，用户只需描述研究意图。

## 判断当前动作

| 用户目标 | 动作与按需读取 |
|---|---|
| 想研究某个问题 / 比较设计 | wfh 主持讨论，读 [研究设计](../wfh-grill/SKILL.md)，沿用已有答案，可提出有依据的候选与推荐，关键决定由作者确认 |
| 整理已确认内容 | 读 [研究方案](../wfh-spec/SKILL.md)，保留来源、主张边界和未决 |
| 安排长期课题步骤 | 读 [步骤安排](../wfh-tickets/SKILL.md)，按证据和依赖组织 |
| 查看进度 | 读 [只读查询](../wfh-ask/SKILL.md) |
| 继续 / 完成当前目标 | 读 [执行协议](../wfh-research/references/execution_protocol.md) 默认分支，在已授权目标内执行、核对和同步 |
| 检索 / 引用核对 / 写作 / 审稿 / 改稿 / 格式 | 读 [ARS 能力选择](../wfh-research/references/ars_intent_map.md)，按模式准备所需输入；论文结构规划交 ARS 主持 |
| 检查结果 | 读 [验收](../wfh-close/SKILL.md)，区分交付完成与科学支持程度 |
| 原解释或设计被否定 | 读 [回环](../wfh-research/references/reopen_template.md)，展示证据及候选路径，请作者确认改变哪些决定 |

独立小请求直接处理，不先建立课题、补完整方案或评分。需要持续跟踪才维护 FLOW；多阶段材料、意图不清或目标包含多个步骤时读 [动作分派](../wfh-research/references/dispatch_protocol.md)。明确只需交接说明时读 [接手准备](../wfh-next/SKILL.md)，其本身不执行。

## 完成边界

同一授权目标内连续完成准备、实际调用、结果检查和记录同步；遇新研究决定、ARS 原生必需确认、人工返回物、关键缺件或范围变化时停下。单说“继续”只恢复当前步骤，不授权整课题连跑。

AI 建议、作者已确认和证据已支持分别记录。只生成说明或读取源码不算 ARS 调用，文件存在不等于结论成立。已有课题记录与证据不一致时先核对；独立请求不强制创建进度文件。收尾说明实际产物、检查范围、遗留和一个下一步。
